# T25: Add a dedup/counting subscriber between system.logs.* and the Telegram notifier

Package: pkg/logger
Generated: 2026-08-31 | Source: user request

Severity: FEATURE | Type: feature

Where: pkg/logger (publishes `system.logs.warn`/`system.logs.error`); pkg/notifier (consumes those subjects and forwards to Telegram).

Why: `NATSHandler` publishes one NATS message per Warn/Error `slog` record, and `notifier.Start` forwards every one of those straight to Telegram. A hot error loop (e.g. a scanner retry storm) currently produces one Telegram message per occurrence, flooding the channel with duplicates and burying unrelated alerts.

What: We need a deduplication and counting stage sitting between the raw log subjects and the Telegram notifier. It should consume the warn/error log messages, recognize repeated/duplicate errors, collapse them, and track how many times each occurred, then publish the deduplicated, counted result onto its own subject. The notifier package should stop consuming the raw log subjects directly and instead consume from this new subject, so what reaches Telegram is already deduplicated and annotated with an occurrence count.

Done when: A hot loop producing many identical Warn/Error log records results in a single Telegram message carrying an occurrence count, rather than one message per record; unrelated log messages are still delivered independently.
